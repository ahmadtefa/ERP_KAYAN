# معرّف الجهاز / Machine identity

## كيف يُحسب / How it is built

على ويندوز: `platform | arch | guid:<MachineGuid>`، ثم SHA-256 وتشفير Base32،
فيظهر بالشكل:

```
KM-XXXX-XXXX-XXXX-XXXX-XXXX
```

`MachineGuid` يُقرأ من
`HKLM\SOFTWARE\Microsoft\Cryptography`، وهو ثابت عبر إعادة تشغيل الجهاز وتغيير
اسمه وتغيير الشبكة.

على غير ويندوز (بيئة الاختبار فقط): `platform | arch | host | mac`.

المعرّف **مشتق لا مخزّن**: لا ملف يُنسخ، ولا يمكن أن يختلف بين خدمة الخلفية وواجهة
سطح المكتب. لا يُرسل تلقائيًا إلى أي مكان؛ يظهر في كود الطلب الذي ينسخه العميل
بيده.

## ما لا يحمله / What the request code carries

`{ v, machineId, installId, appVersion, requestedAt, nonce }` فقط. لا اسم شركة،
ولا رقم ضريبي، ولا بيانات من الدفاتر. يكفي أن يتحقق المورّد أن الطلب جديد وأن
الجهاز هو المقصود.

## تغيير العتاد / Hardware change

| التغيير | الأثر على المعرّف |
| --- | --- |
| تغيير القرص أو الرام أو كرت الشاشة | **لا يتغير** |
| تغيير اسم الجهاز أو الشبكة | **لا يتغير** |
| إعادة تثبيت ويندوز | **يتغير** (MachineGuid جديد) |
| استعادة صورة ويندوز من نسخة قديمة | غالبًا يعود المعرّف القديم؛ يعمل الترخيص إن كان لنسخة سابقة على نفس الجهاز |
| ترحيل إلى جهاز آخر | **يتغير** |

عند تغيّر المعرّف يرى البرنامج أن الترخيص لجهاز آخر، ويطلب ترخيصًا. الحل **مفتاح
نقل** يصدره المورّد: يحمل المدة المتبقية وحد المستخدمين وعدد الحسابات المستخدمة،
فلا يبدأ العدّاد من الصفر ولا تضيع مدة مدفوعة. راجع `OPERATOR-GUIDE.md`.

**توصية للمورّد:** احتفظ في سجلك بآخر معرّف جهاز لكل عميل. تغيّر المعرّف مع طلب
نقل متكرر خلال فترة قصيرة إشارة تستحق سؤال العميل.

## إعادة التثبيت / Reinstalling the program (same Windows)

إعادة تثبيت البرنامج لا تغيّر `MachineGuid`، لكنها تُنشئ قاعدة بيانات جديدة
وتفقد ملف حالة الترخيص. عندها:

- إن كان الترخيص ما زال في قاعدة البيانات المستعادة، يعمل كما هو بعد إعادة
  تشغيل الخدمة.
- إن كانت قاعدة البيانات جديدة، يصبح الترخيص غير مثبّت ويحتاج مفتاح تفعيل
  جديدًا للمدة المتبقية — أصدره بالمدة المتبقية، لا بمدة جديدة.

## الاستعادة من نسخة احتياطية / Restoring a backup

ملف الحالة (`license-state.json`) يحمل أعلى عدد مقاعد مستخدمة وأبعد تاريخ انتهاء
وأعلى حد مستخدمين، فلا تعيد نسخة قاعدة بيانات أقدم تلك الأرقام إلى الوراء.
بعد كل استعادة يستدعي البرنامج `reconcile()`:

- إن كانت قاعدة البيانات **أقدم** من الملف: تُرفع القيم من الملف وتُسجَّل حادثة
  `RESTORED_FROM_WATERMARK`.
- إن كانت **أحدث**: تُحدَّث العلامات المائية من قاعدة البيانات.
- لا تُحذف حسابات ولا تُصفَّر عدادات في الحالتين.

## ما يجب نسخه احتياطيًا / What to include in backups

مجلد حالة الترخيص — `%ProgramData%\KAYAN-ERP\license` (أو `LICENSE_STATE_DIR`) —
يحوي:

```
license-state.json      الحالة الموقّعة (MAC)
state.key               مفتاح التحقق (0600)
public-key.pem          المفتاح العام (إن ثُبّت كملف)
```

نسخه مع نسخة قاعدة البيانات يجعل الاستعادة متسقة. **النسخة الاحتياطية للشركة
(JSON) لا تتضمن جداول الترخيص** عن قصد: ترخيص جهاز لا يجوز أن ينتقل إلى جهاز آخر
عبر نسخة بيانات.
