# سجل وحدات العمل — ERP KAYAN

المرجع التفصيلي السابق: `ACCEPTANCE_TRACKER_17.md`. الحالة هنا لا تعني قبول Windows المثبت. ترتيب العمل أدناه ملزم: لا تنتقل الوحدة إلى «منفذة برمجياً» إلا بعد مراجعة المسارات والاختبارات والنواقص ومخالفات ESLint للملفات المتأثرة. تجنب إعادة تنفيذ الاختبارات المثبتة إلا عند تغيير مساراتها. لم تُثبت الأسباب الأصلية الثلاثة على جهاز المستخدم؛ تحدد اختبارات Windows أدناه طريقة التحقق دون افتراض السبب.

## 1. النسخ والاسترجاع وتحديث البيانات — جارٍ
- النطاق: واجهة `backup_screen.dart` (JSON شركة)، `full_backup_section.dart` (DUMP/KAYANBACKUP والتعافي)، `master_data_backup_actions.dart`؛ مزودات `data_providers.dart` وإعادة إنشاء نطاق التطبيق والجلسة. Backend: وحدات `backup`, `backup/full`, `backup/complete`, النسخ المستقلة للبيانات الأساسية، الصيانة، صلاحيات التشغيل وWindows runtime.
- JSON: تحقق أعداد الصفوف وتصدير `RepeatableRead`، ونجح اختبار PG16 الأصلي مع التراجع وعزل الشركة. أضيف حفظ نسخة شركة تلقائية فريدة قبل الاستبدال مع إعادة القراءة والتحقق ورفض الاستعادة عند الإخفاق أو تجاوز حد الرفع، وصيانة محلية تستنزف الطلبات والمهام المتعقبة؛ التراجع عند فشل المعاملة موجود. نجح اختبار PG16 على `17b6884` للاستعادة من نسخة الأمان وفشل التخزين. أضيف التحقق من عدد الصفوف المُدرج فعلاً من قاعدة البيانات ورفض التعارض بدلاً من إبلاغ عدد مفترض؛ اختبارات الوحدة والبناء واختبار PG على `c903599` ناجحة، وتشغيله الشامل جارٍ. نسخة الشركة ليست نسخة نظام كاملة ولا تشمل الملفات أو الترخيص أو الجلسات؛ الاستعادة منها تتطلب اختيار الملف من مجلد النسخ على الخادم. **فجوات مهمة:** الصيانة محلية فقط؛ قد تكتب عملية أخرى بعد لقطة الأمان وقبل الاستبدال، فلا يُضمن حفظ تلك الكتابات. أضيف قفل PostgreSQL مشترك بين استرجاعات JSON وDUMP وKAYANBACKUP عبر العمليات؛ نجح اختبار PG16 الذي يحجز القفل باتصال منفصل ويثبت رفض JSON ثم نجاح المحاولة بعد إطلاقه. لكنه لا يمنع طلبات العمل أو المهام من العمليات الأخرى؛ يلزم حاجز عابر للعمليات لجميع الأعمال قبل اعتماد الوحدة. أضيف ربط رمز الوصول وتذكرة التنزيل بسجل جلسة لا يتضمن كلمة تجديد الجلسة؛ حذف مستخدمي الشركة عند استعادة JSON يحذف سجلاتهم ولا يعيدها من الملف، حتى إذا تطابق رقم الإصدار. نجح اختبار PG16 لمستخدمين/جهازين للشركة المستعادة ومستخدم للشركة الأخرى، متحققاً من رفض رموز الوصول والتجديد القديمة واستمرار جلسة الشركة الأخرى. الرموز القديمة بلا هذا الرابط ستُرفض بعد التحديث ويجب تجديدها؛ لا تُمس سجلات الشركة الأخرى عند استعادة JSON. أضيف حذف جلسات الأرشيف بعد استعادة DUMP/KAYANBACKUP وبعد التعافي من نسخة الأمان، مع إبقاء الصيانة عند فشل الحذف؛ نجح اختبار PG17 للاستعادة والتعافي وسيناريو HTTP على PG16 مع التحقق من رفض الجلسة القديمة وإعادة الدخول. نجح اختبار DUMP المعزول على PG16 وكذلك تشغيل Actions `45067379506` بكامل مهامه على `0eb6116`. اختبار backup.service.spec.ts يحتوي مخالفات ESLint قديمة عديدة؛ بقية ملفات التغيير اجتازت الفحص.
- DUMP: فحص الملف، تجربة قاعدة منفصلة، نسخة أمان، إيقاف الكتابات، استعادة وفحص واسترجاع عند الفشل — اختبارات PG16 السابقة ناجحة؛ أضيف رفض منافسة الصيانة التي تبدأ أثناء التجربة، واختبار موجه ناجح محلياً؛ **استكمال تدقيق التوافق والتعافي**.
- KAYANBACKUP: التحقق من المحتوى والملفات، تجربة معزولة، نسخة أمان، journal والتعافي عند الانقطاع، الحفاظ على الترخيص — اختبار PG17 للرأس `1513c75` ناجح. أضيف منع حذف سجل استعادة حيّ عند بدء عملية أخرى، ورفض فتح النظام أو بوابة الاستعادة إذا كان السجل تالفاً/غير مقروء أو مفقوداً بعد بدء الاستبدال؛ 44 اختباراً موجهًا وESLint وبناء محلي ناجح، واختبارات PG للرأس الجديد معلقة. أضيف تنسيق مؤقتي التنبيهات والنسخ المجدول مع الصيانة: تُستنزف الدورات الجارية وتُتخطى الدورات الجديدة؛ 37 اختباراً موجهًا وESLint للملفات المتأثرة ناجحة محلياً. **فجوة:** التنسيق محلي للعملية ولا يحمي من عمليات API أخرى أو مهام خارجية، فلا يعد ضماناً عبر العمليات.
- الأصناف والعملاء والموردون: round-trip PG16 سابق ناجح؛ **تدقيق واجهة التحديث بعد الاسترجاع**.
- Windows: على نسخة مثبتة، سجّل بيانات A، خذ نسخة، عدّلها إلى B، استعد كل صيغة متاحة وتحقق من A مباشرة ومن قاعدة البيانات بعد إعادة الدخول، ثم أعد التشغيل وتحقق مجدداً. افتح جلستين على جهازين، واستعد JSON وتحقق من رفض رموز الوصول والتجديد القديمة في الجهازين ثم نجاح إعادة الدخول، وكرر لـ DUMP/KAYANBACKUP؛ تحقق من استمرار جلسة شركة أخرى عند استعادة JSON حيث تتوافر بيانات اختبار معزولة. تحقق من مسار قاعدة البيانات والنسخة والملفات المعروضة في «حول». إذا بقيت B سجّل السجلات والنسخة دون الادعاء بمعرفة السبب.

## 2. كلمة المرور والجلسات — لم تُستكمل الوحدة
- قبل الدخول: تحقق من الشركة والمستخدم والقديمة والجديدة، رسائل عربية، لا تسريب حساب، حظر التكرار؛ اختبارات تغيير متزامن على PG16 ناجحة سابقاً.
- جلسات قائمة: تجديد وتدوير وإبطال آمنين، تسجيل خروج وإعادة تعيين مسؤول، تعافي انقطاع الشبكة وتعدد الطلبات، عدم تحويل فشل كلمة المرور إلى انتهاء جلسة — **مراجعة شاملة معلقة**.
- Windows: جرّب كلمة مرور حالية صحيحة وخاطئة قبل الدخول وبعد إعادة تشغيل التطبيق، وسجّل الاستجابة وهوية واجهة/API إن ظهرت رسالة انتهاء الجلسة.

## 3. الموظفون وصلاحيات المستودعات — لم تُستكمل الوحدة
- حصر إنشاء وتعديل المستخدم والدور والفروع والمستودعات، الفصل بين الصلاحية الوظيفية ونطاق البيانات، عزل الشركة والفرع والمخزن عبر API والواجهة.
- شاشة الإسناد: طلبات التحميل والأخطاء وإعادة المحاولة وعدم انتظار صلاحيات غير مرتبطة؛ حماية منح خارج النطاق وعدم تحويل آخر قيد إلى وصول غير محدود. إصلاحات واختبار PG16 سابقان لا يغنيان عن حصر كافة المسارات.
- Windows: افتح الشاشة كمستخدم يملك عرض الصلاحيات فقط، سجّل الطلبات والأخطاء وزمن الاستجابة إن استمر التعليق.

## 4. التحويلات والتنبيهات — لم تُستكمل الوحدة
- طلب/مراجعة/اعتماد مستقل، صرف جزئي ومتكرر، مخزون بالطريق، استلام جزئي، مرتجع ونقص وتلف واعتماد الفروق وإغلاق وإلغاء؛ منع التكرار والمخزون السالب، تحقق الصلاحيات والنطاق.
- تنبيهات المسؤولين حسب المرحلة، إغلاق وإعادة فتح ودون تكرار؛ سيناريو PG كامل متعدد المستخدمين والواجهة مطلوب. الاختبارات السابقة تشمل PGlite ووحدات وحالات محددة فقط.

## 5. مواقع التخزين والتحقق العربي — لم تُستكمل الوحدة
- أنواع المواقع وتسلسلها والشركة/الفرع/المستودع، إعدادات وعرض وحركات وتحقق الارتباط؛ النماذج كافة عدا عروض الأسعار: حقول مطلوبة وأنواع وقيم، رسائل عربية بجوار الحقل، إبقاء الإدخال، التركيز والتمرير لأول خطأ ومنع الحفظ المزدوج.

## 6. التقارير والأسعار والإحصائيات — لم تُستكمل الوحدة
- حصر جميع endpoints والتقارير والطباعة والتصدير، صلاحية مستقلة لكل تقرير ورفض API مباشر، نطاق الشركة/الفرع/المستودع، إخفاء سعر البيع والشراء والتكلفة والإجماليات وفق الصلاحيات؛ اختبارات أدوار سلبية وإيجابية مع بيانات حقيقية ومتعددة الشركات. لا تعديل لعروض الأسعار.

## 7. قوائم الاختيار بالأسماء — لم تُستكمل الوحدة
- حصر النماذج غير المستثناة، واستبدال إدخال الأكواد لمراجع معرفة مسبقاً باختيار قابل للبحث باسم عربي/إنجليزي مع المعرف داخلياً، النطاق والتحميل والحالات الفارغة والتحقق؛ اختبارات التحديد والحفظ.

## 8. التمرير — لم تُستكمل الوحدة
- حصر الصفحات والنماذج والحوارات والجداول والتقارير عدا عروض الأسعار؛ تمرير أفقي ورأسي ظاهر وقابل للاستخدام بالماوس/اللمس ولوحة المفاتيح وRTL، عند النوافذ الضيقة وتكبير النص. تحقق سلوكي؛ إصلاح تفاصيل التحويل واختبارها السابق لا يثبت بقية الشاشات.

## قيود ثابتة
العمل والرفع للفرع الحالي فقط، دون دمج أو Installer أو مساس بـ PR #84 أو عروض الأسعار أو Supabase أو الترخيص أو بيانات المستخدم ومجلد التسليم؛ المحافظة على بنية Windows offline/cache والنسخ والترقية وإلغاء التثبيت. الاختبارات الموجهة أثناء العمل ثم الشاملة بعد وحدة مترابطة؛ لا حذف أو تعطيل اختبارات أو تجاوز صلاحيات. لا يوجد Flutter أو PostgreSQL حقيقي محلياً؛ تستخدم Actions عند الحاجة.
