والتجديد القديمة واستمرار جلسة الشركة الأخرى. الرموز القديمة بلا هذا الرابط ستُرفض بعد التحديث ويجب تجديدها؛ لا تُمس سجلات الشركة الأخرى عند استعادة JSON. أضيف حذف جلسات الأرشيف بعد استعادة المعزول على PG16 وكذلك تشغيل Actions `45067379506` بكامل مهامه على `0eb6116`. اختبار backup.service.spec.ts يحتوي مخالفات ESLint قديمة عديدة؛ بقية ملفات التغيير اجتازت الفحص.

- KAYANBACKUP: التحقق من المحتوى والملفات، تجربة معزولة، نسخة أمان، journal والتعافي عند الانقطاع، الحفاظ على الترخيص — اختبار PG17 للرأس `1513c75` ناجح. أضيف منع حذف سجل استعادة حيّ عند بدء عملية أخرى، ورفض فتح النظام أو بوابة الاستعادة إذا كان السجل تالفاً/غير مقروء أو مفقوداً بعد بدء الاستبدال؛ وفحص السجل تحت قفل الاستعادة قبل بدء JSON وDUMP وKAYANBACKUP لتجنب تجاوز تعافٍ معلق. اختبارات الوحدة والبناء محلياً ناجحة، وجميع مهام Actions `45070798153` على `b01a34b` ناجحة، بما فيها PG16 وPG17؛ نجح اختبار PG بعملية مستقلة تملك قفل الاستعادة، ثم قتلها واختبار احتفاظ العملية الأخرى بالسجل ثم تنظيف السجل غير المدمر بعد تحرير PostgreSQL للقفل؛ لا يمثل الاختبار عمليتي API كاملتين ولا يثبت استنزاف طلباتهما. أضيف أيضاً flush لملف السجل ودليل الاسم على POSIX واشتراط حذف السجل بنجاح قبل إنهاء الصيانة؛ على Windows لا توفر Node مزامنة دليل محمولة ويجب اختبار انقطاع الطاقة على النسخة المثبتة. هذا يفترض مجلد نسخ مشتركاً بين العمليات ولا يغني عن الحاجز العابر للعمليات. أضيف تنسيق مؤقتي التنبيهات والنسخ المجدول مع الصيانة: تُستنزف الدورات الجارية وتُتخطى الدورات الجديدة؛ 37 اختباراً موجهًا وESLint للملفات المتأثرة ناجحة محلياً. **فجوة:** التنسيق محلي للعملية ولا يحمي من عمليات API أخرى أو مهام خارجية، فلا يعد ضماناً عبر العمليات.
