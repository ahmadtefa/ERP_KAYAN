### البند 9 — أثر `allowExpiredIssue` (قيد حقيقي)

```ts
const allowExpired = input.allowExpired ?? policy.allowExpiredIssue;
if (allowExpired && (input.allowExpired ?? false)) { /* افحص الاعتماد */ }
```

الحارس يعمل **فقط** عندما يُمرَّر `allowExpired: true` صراحةً من الخدمة. أما إذا كان الصنف مهيّأً في سياسته بـ`allowExpiredIssue = true`، فإن `allowExpired` يصير `true` من السياسة، لكن الشرط الثاني `(input.allowExpired ?? false)` يبقى `false` — **فيمرّ الصرف المنتهي بلا اعتماد ولا سجل**.

**الأثر:** صنف تُفعَّل له سياسة الصرف المنتهي يبيع منتهيًا بلا صلاحية `inventory.batches.expired.issue` وبلا سبب موثّق. هذا يعني أن الفرض على مستوى الصلاحية **قابل للتجاوز** عبر إعداد الصنف.

**هذا مذكور في تقرير FEFO السابق كقيد مقصود**، لكنه في الحقيقة **ثغرة**، لا قيد تصميم مقبول: سياسة الصنف قرار دائم، بينما المطلوب أن كل عملية صرف منتهٍ تُسجَّل بمن اعتمدها. **لم أغيّر الكود** (المهمة فحص فقط)، لكن يجب إصلاحه قبل الاعتماد.
